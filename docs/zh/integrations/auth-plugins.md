# 其他认证插件

## 经典源码中存在的钩子

| 平台 | 候选钩子 |
| --- | --- |
| Bukkit/Folia | AuthMe, CrazyLogin, LogIt, LoginSecurity, UltraAuth, xAuth, Passky |
| BungeeCord | BungeeAuth |
| Velocity | 没有原生认证账号钩子, 协调参与认证的后端 |
| Fabric | 专用 EasyAuth 集成, 不是经典通用钩子 API |

这是实现清单, **不保证**所有历史或未来版本可用. 部分集成使用旧 API/本地编译 JAR. 应验证实际插件版本, 服务端, 线程模型和启动时选中的钩子. 每个后端优先保留一个认证负责人; 多个候选同时安装时, 选择顺序不是多认证插件组合系统.

## 能力不能互换

通用钩子提供不同程度的注册/登录/账号检查, 不会自动具有 AuthMe 6 的前置对话框, 安全占位账号释放, 正版 UUID 记录或 cracked 清理. 曾自动生成随机密码的插件, 在玩家切回 cracked 时可能需要使用它自己的恢复流程.

Folia 要求认证插件本身支持 Folia. 把 Bukkit FLP 换成 Folia FLP, 不会自动适配其他插件的调度器调用.

BungeeAuth 钩子与后端 AuthMe 不同, 也不创建代理原生 `/flp` 管理命令. 没有明确所有权和身份模型时, 不要组合多套独立自动登录系统.

## 声明某个组合可用之前

检查首次注册, 已有密码登录, 返回正版登录, 关闭自动登录, 账号切换, 断线重连, 读写失败和重启持久化. 真实客户端证据与模拟单元测试/编译通过分开记录. 出现 API/版本不支持时应报告, 不要移除安全检查.
