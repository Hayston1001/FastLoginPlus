# 安装验证与安全检查

请使用测试环境和可丢弃账号, 不要对没有备份的生产账号测试破坏性命令.

## 启动与网络检查

- 确认各端 FLP 构建/提交, 平台产物, 认证插件和 Java 版本.
- 确认认证钩子, 数据库和语言文件加载无错误. Fabric 应报告 EasyAuth 策略与存储兼容情况.
- 代理后端核对转发模式, 必要的 matching forwarding secret 和重启后生效的 FLP 代理 ID.
- 从受信任网络外尝试连接后端. 必须被阻断或拒绝未认证的转发. 只有白名单文件不够.
- 独立服检查数据包库兼容性, 尤其是加密响应拦截. 必要时临时开启 debug.

## 客户端测试矩阵

| 情景 | 检查内容 |
| --- | --- |
| 新的正版持有人, 没有本地账号 | 仅在策略允许时自动注册/登录, 否则正常注册 |
| 已有密码账号 | 不能被意外免密接管; 登录后的持有人可请求绑定 |
| 返回的已绑定账号 | 正确的已验证持有人成功, 未验证或冲突身份不能绕过认证 |
| `autoLogin: false` | FLP 不提供免密登录, 保留认证插件流程和账号安全 |
| `auto-register-unknown: false` | 不自动创建缺失的本地 Java 账号 |
| 白名单开启时的未知离线名字 | 被拒绝; 已知 cracked 记录仍然需要密码 |
| 验证或命令过程中断线 | 不误报成功, 不影响其他连接; 重试前检查持久化状态 |
| 切换后的手动重连 | 应用预期路径与 UUID, 不期待自动重连 |
| 后端/代理重启 | 信任配置与账号变化按预期保留 |

Floodgate 要测试所配置的 linked 和名字冲突策略. Fabric 只测试文档允许的已有账号路径, 并确认不会静默放行新账号或 linked 账号. Folia 除玩家看到的结果外, 还应检查调度与线程错误.

## 故障检查

在测试环境模拟 Mojang 不可用, 认证/FLP 数据库不可读, 信任配置缺失和账号写入失败. 读取失败不是账号不存在, 未验证连接不能获得免密权限. 同时检查玩家反馈与重连/重启后的数据库内容. 测试后恢复正常网络和配置.

证据应分开记录: 编译 JAR, 启动服务端, 真实客户端登录和故障注入证明的内容不同. 本手册是核对源码后的说明, 不是所有组合都通过该矩阵的声明.
