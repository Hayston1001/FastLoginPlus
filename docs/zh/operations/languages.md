# 语言, 日志与更新检查

## 选择语言

经典平台在自己的 `config.yml` 设置 `language`, 从该进程插件目录加载 `messages_<语言>.yml`. 内置 `en` 和 `zh`, 可以用 `ja` 等自定义代码配合 UTF-8 文件. 无效代码回退英文. 代理与后端可使用不同语言, 因为各自负责自己的消息.

Fabric 在 `config/fastloginplus-fabric.yml` 设置 `language`, 可在 `config/fastloginplus-fabric/messages_en.yml` 或 `messages_zh.yml` 覆盖. 支持 `en`/`zh`, 其他非空值告警并使用英文, 重启后应用.

## 缺失与过期消息

语言文件带 `_messages-version`. 启动时优先按内置选定语言补齐缺键, 英文兜底. 版本迁移可刷新能识别的旧默认值或误填英文默认值, 不覆盖真正自定义的值. 多余键保留并诊断, 不会静默删除. 不要手改版本标记来压制迁移.

YAML 损坏会报告并使用内置消息, 不使整个插件失效, 但不代表自定义文件已修好. 应修正语法并重启. 配置模板刷新与语言升级是不同机制, 语言覆盖文件保留注释/顺序, 不会整份重生成.

保留消息键与替换标记拼写. 经典平台有自己的颜色/多行约定, Fabric 使用独立的字符串转组件与扁平 YAML 限制. 不要假设各平台对空值, 多行转义和标记处理完全一致, 应参照对应平台生成/内置文件.

## 诊断日志

在需要排查的进程设置 `debug: true` 并重启. 诊断消息使用插件常规日志级别, 不必调整日志框架 DEBUG 阈值. 代理问题要收集同一次连接的两端日志.

复现后关闭诊断. 发布日志/配置前移除数据库密码, forwarding secret, 代理 ID 和个人信息. 不公开生成的认证凭据或整个认证数据库.

## 更新检查

`check-update: true` 开启后台 GitHub 发布检查. `update-check-interval: 24` 的单位是**小时**. 它不会下载/安装 JAR 或重启服务器. 经典后端可以通知管理员, Fabric 在日志报告更新. 检查器网络失败不代表玩家认证失败.

仍携带旧版本标签的开发构建, 比较结果不等同于未来正式 1.0.0. 报告问题应记录实际提交, 见[问题反馈](reporting.md).
