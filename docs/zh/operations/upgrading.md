# 备份, 升级与回退

本手册面向尚未发布的 1.0.0. 标记为 0.7.0 的 JAR 不一定包含这些行为, 开发产物还应检查提交编号. 实际安装时阅读该构建的[发布说明](https://github.com/Hayston1001/FastLoginPlus/releases).

## 一致性备份

停止相关进程, 或使用数据库支持的一致性备份方式. 保存:

- FLP 配置, 语言与 SQLite 数据库, 或一致的 MySQL/MariaDB 导出.
- AuthMe/EasyAuth/其他认证插件数据, 配置和数据库.
- Velocity `proxyId.txt`, BungeeCord `stats` UUID, 后端 `allowed-proxies.txt` / Fabric `allowed-proxy-ids`, 以及安全保存的 forwarding secret.
- 经典 `pending-relay.json`, 因为尚未送达的管理请求重启后仍存在.
- 世界/玩家数据和其他按 UUID 存储的插件记录, 旧 JAR 及准确版本.

在隔离环境测试恢复. 只复制 FLP 数据库不构成账号或背包恢复方案.

## 升级步骤

1. 在测试环境复现网络, 记录现有 UUID 策略, 认证方式和账号类型.
2. 停止相关代理/后端, 安装匹配的平台产物, 保留数据/配置/信任身份. 不使用 `-plain.jar`, 不同时部署多个 FLP 版本.
3. 优先在同一维护窗口升级两端. 较旧环境滚动升级要考虑后端消息标记和声明策略兼容性: 强制代理检查之前应先升级未带标记的旧后端; 代理提供策略事实之前不要开启后端严格声明要求. 不存在适用于所有混合版本的通用安全顺序.
4. 启动后检查配置/语言迁移告警, 信任列表, 数据库错误和认证接管. 原配置值通常保留, 新默认值不会自动覆盖所有旧值.
5. 按[清单](../installation/verification.md)检查正版, 密码, 白名单, 切换, 重连及失败路径, 确认最终数据库结果, 不只检查启动成功.
6. 仅在实际组合通过检查后重新开放, 保留可用的恢复管理员.

不要把已删除的 `anti-bot.action`, Fabric 旧 `.properties`, transfer/cookie 绑定说明和旧一次性回退语义复制进新配置. 应重新阅读[策略参考](../configuration/java.md).

## 回退

回退前停止写入. 旧插件可能错误理解新结构/账号状态, 转换账号之后不能只换旧 JAR. 应恢复兼容且协调的 FLP 与认证备份, 玩家数据变化另行评估. 回退时仍在队列里的命令可能在以后重新应用旧管理意图.

不要把重新生成代理 ID 或清空数据库当成常规回退步骤. 没有备份或两份存储不一致时, 保留证据, 由管理员核对所有权后修复, 不要直接放行所有登录.
