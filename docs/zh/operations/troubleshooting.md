# 常见问题与故障排查

从一次可复现尝试开始, 记录部署, 准确版本, 账号状态, 策略及玩家看到的结果. 先保留两端日志, 不要反复修改无关开关.

## 正版玩家仍然需要密码

1. 确认当前连接确实通过 Mojang 验证, 名字查询, 皮肤和已存 UUID 都不够.
2. 检查 FLP 的 `autoLogin` 和认证插件中的账号状态. 代理部署应检查代理配置. 未同意绑定的密码账号仍需密码是正常的.
3. 没有账号时检查 `auto-register-unknown`, 关闭后应进入注册.
4. 使用代理时, 按安装指南检查转发配置, 密钥和后端允许的代理 ID.
5. 持有人登录后再按[绑定流程](../accounts/binding.md)操作.

## 卡在 AuthMe 登录对话框

1. 确认 AuthMe 和 FLP 版本与服务端兼容, 并查看两者的启动日志.
2. 使用代理时, 按安装指南检查转发模式, 密钥和后端允许的代理 ID.
3. 检查账号是否已有密码, 以及代理和后端日志是否报告账号或注册错误.
4. 仍无法解决时, 保留账号数据并[报告问题](reporting.md). 不要为跳过对话框而删除账号或随意切换 UUID.

## 代理请求没有效果

- `/flp` 在后端执行, 不是代理控制台.
- 核对已生成代理 ID, 后端信任列表及必要重启. 空信任阻止消息操作.
- 检查 `verify-backend-messages` 和旧端策略兼容, 不要永久关闭检查来掩盖错误.
- Bukkit/Folia 后端空服时, 待发送请求会等待该后端有玩家上线. Fabric 空服时, 需要转发的控制台请求会直接失败.
- 区分即时转交与最终结果, 收集代理日志, 后端反馈和真实数据库状态.

## Mojang 不可用 / invalid session

未完成查询会提示认证服务问题并拒绝, 不会作为新 cracked 账号保存. `invalid-session` 可能是明确的会话拒绝, 让玩家刷新启动器会话并使用正确地址. 检查 DNS/TLS/出站连接和限流. 代理原生验证不受 FLP 重试次数控制, 连续重连可能加重限流.

## 账号归属冲突 / UUID 损坏

保留原记录, 由管理员核对准确名字, 已验证 UUID, 同意和本地账号. 不匹配, 已存 UUID 格式错误和读取失败都不代表新空账号. 从可信备份恢复/协调, 不要粘贴申诉人提供的 UUID 或直接删库.

## 关闭自动登录后正版账号无法登录

`autoLogin: false` 本来就阻止免密动作, 包含已转换账号. 部分账号没有可用密码. 应按认证插件和[切换规则](../accounts/binding.md)恢复, 不能认为所有正版账号都曾生成过密码.

## 背包或权限变了

对比前后连接 UUID 和 `premiumUuid` 设置. 代理部署应查看代理配置. FLP 不迁移按 UUID 保存的数据. 在测试副本恢复或单独迁移对应插件数据, 不要在玩家在线时覆盖世界文件.

## Fabric 拒绝登录或管理操作

检查 Minecraft/EasyAuth 版本, modern forwarding, `config/fastloginplus-fabric.yml`, 可信 ID 及全部 EasyAuth 必要策略. 注意存储告警, 非 SQLite 未验证安全. Bedrock 新账号/linked 不在支持范围. 修改配置需要重启后端, 没有 `/flp reload`. 控制台命令需要在线载体.

## 很多玩家共享限流 / 皮肤或占位符异常

提高反机器人阈值前先验证真实 IP 转发. 纹理问题检查代理 `forwardSkin`, SkinsRestorer 自定义状态和档案缓存. 占位符检查 Bukkit/Folia 扩展, 并记住它只展示缓存状态, 不证明认证成功.

独立服出现 ProtocolLib 加密响应映射告警时, 开启 debug 并用真实客户端验证服务端/数据包库组合. 不要以为版本号越新越能拦截, 也不能因进入密码流程就认定告警无害.

仍不能解释时, 提供最小化且脱敏的复现步骤[报告问题](reporting.md).
