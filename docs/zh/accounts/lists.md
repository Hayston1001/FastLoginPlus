# Premium/cracked 名单与准入

## 两张逻辑名单, 一个权威来源

Java 登录使用 premium 名单与 cracked/非 premium 名单, 实际记录在同一张 FLP 表里, 不是互相竞争的数据库. `/flp premium` 和 `/flp cracked` 修改名单状态; `offline-whitelist` 读取已知名单, 不创建第三种身份来源.

代理模式以代理 FLP 数据库为准. AuthMe/EasyAuth 账号是**本地认证状态**, 不是 FLP 名单成员关系. 创建或删除认证账号不会自动同步 FLP 名单, 删除 FLP 记录也不是重置认证账号.

## 已记录的事实不全是同意

| FLP 字段 | 含义 |
| --- | --- |
| `UUID` | 用于路由和名字匹配的 Mojang 身份观察, 不是当前连接通过验证的证明 |
| `Premium` | 供正版登录路径使用的同意/已确认正版账号结果 |
| `SameNameCracked` | 回退开启时, 未同意名字的一次已结算正版验证失败的持久化观察 |

管理员显式启用 premium 时也可以通过查询填入 UUID. 查询仍然不能认证后续客户端. 不要手改这些列绕过所有权检查.

已同意 premium 的名字连接时仍需验证. 已知 cracked 名字通常进入密码路径. 只有正版 UUID 观察而没有同意时, 仍可能请求验证, 但后端在不允许访问之前保留已有密码账号保护.

## 离线白名单

`offline-whitelist: true` 时拒绝未知离线 Java 名字, 已知离线名字可以进入认证. 正版路径仍需通过正版验证. 只有认证插件账号, 不代表 FLP 已经知道这个离线名字.

允许离线名字进入时, 在后端执行有权限的 `/flp cracked <玩家>`. 删除非 premium FLP 记录使用 `/flp delete <玩家>`. Premium 记录不能直接删除, 应先检查账号并明确执行切换. 名单不能替代密码, Mojang 验证或 Floodgate 验证.

## 同名离线回退

`secondAttemptCracked` 默认 `false`. 开启后, 未同意名字的一次已结算明确失败, 可以让后续连接转向密码路径并持久化 `SameNameCracked`. 首次记录变化会发送一次提示, 指向 `/flp premium`.

- 冒用者尝试连接, 不会让已同意的名字降为密码路径.
- 独立服区分会话明确拒绝, 会话服务不可达和验证中断.
- 代理不暴露相同的验证结论. FLP 稍后通过服务可达性检查结算未验证尝试. Mojang 可达但玩家网络断线时, 也可能被计为失败, 不能完美证明客户端是离线客户端.
- 验证成功或显式 premium/cracked 操作会清除观察. 选项关闭时忽略该观察, 加载时也会清理.

不了解取舍时保持关闭. 不要把它当成 Mojang 故障或代理配置错误的通用修复方式.
