# Premium/cracked 名单与准入

## 启用离线白名单

{% hint style="warning" %}
**操作前备份认证数据库.** `/flp cracked` 可能改变已有账号, AuthMe 尤其可能删除或重置账号记录.
{% endhint %}

1. 停止服务器. 使用代理时停止代理并编辑代理的 FLP 配置; 独立服编辑本机 FLP 配置.
2. 将 `offline-whitelist` 设置为 `true`, 然后启动服务器.
3. 在后端以有权限的管理员身份执行 `/flp cracked <玩家>`, 将需要允许的离线玩家加入名单.
4. 使用测试账号确认已知玩家可以进入认证流程, 未知离线玩家被拒绝.

{% hint style="info" %}
已有认证插件账号不代表 FLP 已经知道该名字. 白名单不代替密码, Mojang 或 Floodgate 验证. 管理员命令及权限见[命令与权限](commands.md).
{% endhint %}

## 删除非正版名单记录

1. 确认目标名字和账号状态, 并备份 FLP 与认证插件数据.
2. 在后端执行 `/flp delete <玩家>`, 等待最终结果.

{% hint style="info" %}
`/flp delete` 不直接删除 premium 记录, 也不等同于重置认证插件账号. 正版记录需要先检查账号并明确切换. 切换可能改变或清除认证插件账号, 操作前阅读[绑定与切换](binding.md).
{% endhint %}

## 名单的作用

FLP 区分正版名单和非正版名单. `/flp premium` 和 `/flp cracked` 用于切换名单状态; `offline-whitelist` 使用这些已知记录限制玩家进入.

代理模式以代理 FLP 数据库为准. AuthMe/EasyAuth 账号是**本地认证状态**, 不是 FLP 名单成员关系. 创建或删除认证账号不会自动同步 FLP 名单, 删除 FLP 记录也不是重置认证账号.

名单中的正版玩家每次连接仍需通过验证. 非正版玩家通常使用密码登录. 不要直接修改数据库来绕过账号归属检查.

## 同名离线回退

`secondAttemptCracked` 默认 `false`. 开启后, 对尚未同意正版绑定的名字, 一次确认的正版验证失败可能让后续连接改用密码登录. 第一次发生变化时会提示使用 `/flp premium`.

- 冒用者尝试连接, 不会让已同意的名字降为密码路径.
- 独立服区分会话明确拒绝, 会话服务不可达和验证中断.
- 代理模式无法完全区分验证失败与玩家网络中断. 即使 Mojang 服务可用, 玩家断线也可能被计为失败.
- 验证成功或执行 premium/cracked 操作会清除之前的回退记录.

不了解取舍时保持关闭. 不要把它当成 Mojang 故障或代理配置错误的通用修复方式.
