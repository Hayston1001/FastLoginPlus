# 绑定与切换

权限和控制台限制见[命令说明](commands.md). 账号动作应由已经登录的持有人或获得授权的管理员执行. 名字看起来属于正版账号, 不代表可以覆盖别人的账号.

保留认证插件对未登录命令的限制. 不要为了登录前能执行 `/flp`, 就把账号管理命令加入未认证放行名单. 经典命令的权限检查本身不是密码认证.

## 经典 Bukkit/Folia 账号

1. 自助操作前先完成认证插件登录. 执行 `/flp premium`, 只有收到 premium-warning 确认提示时才再次执行.
2. 代理模式下后端转发请求, 代理修改 FLP 名单. 等待**最终**结果, 不要只看已转发提示.
3. `kick-toggle` 开启时代理/服务器会踢出对应玩家, 否则保留当前会话. 玩家手动重连后进入新路径并证明正版身份.
4. 测试下次登录并记录连接 UUID. 命令不会替后续连接完成认证, 也不迁移玩家数据.

`/flp cracked` 清除 FLP 正版状态并改变后续路径. **AuthMe 清理具有破坏性:** 当前经典集成会删除/重置账号记录并清除正版缓存, 可能需要重新注册. 不要假设原密码会保留. 其他认证插件通常没有等效清理, 自动生成过的密码可能需要管理员恢复.

经典独立服的他人命令与代理转发命令, 踢出行为不完全相同. 应根据实际反馈安排手动重连, 不要承诺所有管理员命令都会立即踢出目标.

## Fabric/EasyAuth 密码账号绑定正版

1. 先登录已有 EasyAuth 密码账号, 持久化状态必须是正常一致的密码账号.
2. 执行 `/flp premium`. 请求使用通用代理切换通道. `premium-warning: true` 时, 按代理提示再次执行确认.
3. 代理记录同意并解析目标 Mojang UUID. `kick-toggle` 开启时踢出, 否则玩家自行退出并手动重连.
4. 后续连接必须通过 Mojang 验证, 并满足账号和同意检查, 后端才转换账号并完成 EasyAuth 登录.

原密码会保留为暂不使用的凭据, 不会替换成随机密码. 请求已发送不代表转换完成. 当前流程没有 transfer, cookie 或十分钟的后端临时绑定窗口. 代理信任缺失, 持久化失败或断线时, 先检查两端再重试, 不要删除原密码账号.

管理员可以执行 `/flp premium <玩家>` 授权, 无需证明目标密码. 这是显式特权操作, 不是普通自助绑定. 仍然需要后续通过验证的连接, 也不会删除密码.

## Fabric/EasyAuth 切回密码或注册

- 已绑定且保留密码时, `/flp cracked` 解除本地正版绑定并恢复密码路径, 保留该凭据.
- 已绑定但**没有密码**时, 命令先警告将开放名字重新注册. **30 秒内**重复相同操作确认, 才释放到注册状态, 而不是提供一个不存在的密码. 应安排安全的重新注册窗口, 因为下一位注册者可能取得账号.
- 自助 cracked 命令受管理员权限限制, 且要求已登录账号. 管理员可以指定其他名字.
- `/flp delete <玩家>` 只请求代理删除非 premium FLP 记录, 不删除 EasyAuth 账号; 已绑定的本地账号需要先处理.

这些操作涉及代理记录和本地 EasyAuth 存储, 不是跨库事务. 已发送代理请求后本地写入失败, 可能留下需要管理员协调的状态. 检查日志和持久化记录, 再测试重连及重启.

## 恢复注意事项

先备份两个存储, 使用准确名字, 区分 FLP 同意与认证插件所有权. 不要手工挂上受害者 UUID 来"修复"归属冲突. 恢复备份和切换 UUID 策略也可能影响背包及权限, 见 [UUID 与玩家数据](uuid.md).
