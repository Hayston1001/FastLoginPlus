# 登录方式

## 身份验证不等于获得账号访问权

名字查询回答 Mojang 是否存在该 Java 账号. 登录握手证明**当前连接**是否持有该身份. 单凭任何一个查询, 都不能决定是否应该打开本地已有的密码账号.

代理网络中, 代理验证身份, 控制准入/转发并持有 FLP 记录. 后端结合可信身份和策略事实及认证插件的本地账号状态, 选择并执行账号动作. 独立服上这些职责在同一端完成; 通用独立服认证钩子保留自身的强制登录行为, AuthMe 另有前置所有权检查.

## 常见结果

| 身份与本地账号 | 预期路径 |
| --- | --- |
| 已验证 Java 身份, 没有账号 | `autoLogin` 和 `auto-register-unknown` 允许时自动创建并登录, 否则进入注册 |
| 已验证 Java 身份, 已有密码账号但未同意绑定 | 使用密码认证, 不按名字接管账号 |
| 已验证身份, 具有允许的同意或匹配的正版归属账号 | 策略与账号一致性允许时免密登录 |
| 未验证连接访问普通密码账号 | 密码登录 |
| 未验证或冲突连接访问正版归属账号 | 拒绝, 而不是解锁 |
| 无法读取账号状态 | 保持认证锁或拒绝, 不能把错误当成创建/打开账号的许可 |

[AuthMe](../integrations/authme.md), [EasyAuth](../integrations/easyauth.md) 和[其他钩子](../integrations/auth-plugins.md)的账号能力不同. `autoLogin: false` 时, 即使身份验证成功, FLP 也不提供免密访问. 已转换且没有可用密码的账号可能需要管理员恢复, 不能承诺所有账号都能靠密码对话框自助恢复.

## 几个注册控制项并不相同

- `autoRegister` 参与选择新的 Java 名字进入验证, 不是所有注册路径的总开关.
- `auto-register-unknown` 控制为已经验证的 Java 身份自动创建缺失的本地账号.
- `autoLogin` 控制免密账号动作.
- `offline-whitelist` 根据 FLP 已知名单控制准入, 不认证或注册密码账号.
- Floodgate 有独立的身份和自动认证策略.

例如关闭 `autoRegister`, 不代表返回的 premium 记录, 改名处理或准入策略不会再请求验证. 组合修改之前先看[配置参考](../configuration/java.md).

## 失败与重试

没有完成的 Mojang 名字查询, 不能证明玩家是离线身份. FLP 会拒绝这次不确定查询, 而不是因为查询失败就创建新的密码账号. 会话被明确拒绝, 服务故障和客户端中途断线也不同. 代理对失败原因的判断存在边界, 见[回退语义](lists.md).

"请求已转发", "身份已验证"和"账号已登录"是不同阶段. 只有确认账号动作完成才算免密登录成功. 不要为了消除报错而移除账号保护.
